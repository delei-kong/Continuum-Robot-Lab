# 正向多绳动力学数据闭环设计

> 状态：M1 自动验证通过，等待 GUI 人工验收
>
> 日期：2026-10-05

## 目标与边界

本链路为 Koopman 建模提供直接动力学数据：

```text
当前机器人状态 + 实际绳索动作 → 下一机器人状态
```

它使用 `Trunk(inverseMode=False)` 和 `CableConstraint`，不经过 inverse QP。现有 inverse QP/PID
tracking 仅保留为回归、可达性和展示基线，不能混入本数据集。

## 第一版合同

- 动作：8 根绳的位移命令，先经非负、幅值和单步变化率安全层，再写入 SOFA；
- 状态：8 绳实际位移与力、末端位置、10 个中心线点的位置和速度；
- 激励：固定 seed 的多正弦多绳输入，先静置再激励；
- 产物：`config.json`、`effective_config.json`、`episode.csv`、`metadata.json`、日志、退出码和
  `COMPLETE`/`FAILED` 标记。

动作安全、配置验证和激励生成位于 `src/simulation/forward_data.py`，因而能够在没有 SOFA 的本地环境中测试。
场景适配位于 `src/simulation/scenes/trunk_forward_data.py`；用户通过
`scripts/experiment/run_forward_data.py` 选择已注册的数据输入、运行模式和输出 run ID。Shell 仅承担
统一运行内核的本地 SSH 或远端工作区边界，不承载场景或数据参数。

## Pilot 结果

配置 `trunk_forward_multisine_pilot.json` 在远端完成两次 batch：

| Run ID | 步数 | 结果 |
|---|---:|---|
| `20261005_trunk_forward_multisine_pilot_v1` | 1000 | `COMPLETE`、无非有限值 |
| `20261005_trunk_forward_multisine_pilot_v2` | 1000 | `COMPLETE`、与 v1 的 `episode.csv` SHA-256 一致 |
| `20261005_trunk_forward_multisine_manifest_v1` | 1000 | 通过统一 Python 入口、manifest 与回传 verifier |

每个 episode 有 92 列，包含完整的动作、绳索遥测、末端与中心线动态。v1 中末端在三个坐标轴均发生变化，
各绳命令和约束力均有非零范围，说明采集的不是静态或单绳数据。

后续所有正式数据采集均通过以下受控入口选择注册配置，而不使用场景专用 Shell：

```bash
python scripts/experiment/run_forward_data.py \
  --input multisine_pilot --output <run_id> --mode batch --target <local|server>
```

`scripts/remote/run_experiment.sh` 和 `scripts/server/run_experiment.sh` 仅作为本地 SSH 与远端运行边界，
不接受场景路径、数据参数或任意配置覆盖。

## M1 剩余门禁

需由用户在远端 XFCE 中确认多绳激励下的形变连续、稳定、无明显跳变或发散，并回传对应 GUI 运行的
标准产物。通过后才能进入正式数据集设计与 Koopman 建模。
