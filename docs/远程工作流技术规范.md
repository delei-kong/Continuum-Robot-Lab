# 远程工作流技术规范

> 本文档承载[本地开发与远程实验工作流 SOP](./本地开发与远程实验工作流SOP.md)中不适合放入主流程的路径、环境、同步、运行、验收和安全规范。

## 1. 架构与路径

### 1.1 单一代码源

| 角色 | 路径 | 职责 |
|---|---|---|
| 本地权威项目根 | `/Users/tory/Desktop/workspace/Continuum-Robot-Lab/workspace` | 代码、配置、文档和 Git 的唯一权威来源 |
| 远程执行镜像 | `/root/gpufree-share/Continuum-Robot-Lab/workspace` | 保持相对路径不变，用于执行 |
| 远程可重建运行时 | `/root/gpufree-data/continuum-runtime` | Conda/venv、SOFA、缓存和临时高速数据 |
| 本地实验输出 | `outputs/` | 日志、指标、图表、必要视频和最优模型 |
| 本地科研数据 | `datasets/` | 仿真轨迹、外部数据和处理后的训练数据 |

远程紧急调试产生的源码修改，必须在下一次运行前在本地复现。不允许本地和远程形成两个长期分叉的版本。

### 1.2 存储分工

- `/root/gpufree-share`：持久存储，放置代码镜像、运行日志和关键结果。
- `/root/gpufree-data`：实例级临时高速盘，只放可重建环境、缓存和临时数据。
- 系统盘 `/`：只保留必要系统文件和工具。
- 重要结果不得只保存在临时高速盘。

## 2. 本地连接配置

复制 `scripts/remote/config.example.sh` 为 `scripts/remote/config.local.sh`，并配置：

- `REMOTE_HOST`、`REMOTE_PORT`、`REMOTE_IDENTITY`；
- `REMOTE_PROJECT_PARENT`、`REMOTE_PROJECT_ROOT`；
- `REMOTE_RUNTIME_ROOT`、`REMOTE_CONDA_ENV`；
- SOFA 版本、安装根目录和 Python 环境。

`config.local.sh` 已被 Git 和工作区同步排除。脚本从本地配置读取地址和路径，不得在可提交文件中硬编码实际 IP、端口或私钥路径。

SSH 使用项目专用 Ed25519 私钥。首次连接需核对主机指纹；项目已知主机记录保存于本地 `.remote/known_hosts`。

## 3. 代码同步合同

### 3.1 标准同步

```bash
scripts/remote/sync_workspace.sh
```

脚本会：

1. 为可同步文件生成 SHA-256 清单；
2. 将本地 `workspace/` 打包并通过 SCP 上传到远端临时接收区；
3. 在应用上传内容前，将远端源码与上次成功清单完整比较；
4. 远端漂移时返回退出码42并拒绝覆盖；
5. 将本地已移除的旧受管文件移入远端 `.sync-trash/`；
6. 在远程同名路径解压并逐文件校验；
7. 输出 `workspace_sync_verification=passed`。

同步默认排除：

```text
.git/  .remote/  .venv/  datasets/  outputs/  runs/  checkpoints/
scripts/remote/config.local.sh
__pycache__/  .pytest_cache/  .ipynb_checkpoints/  .mypy_cache/  .ruff_cache/
*.pyc  *.pt  *.pth  *.mp4  .DS_Store  ._*
```

同步使用本地和远端进程锁，避免并发上传。远端源码出现修改、新增或删除时不会继续同步；历史受管文件不会直接删除，而是移动到远端项目父目录的 `.sync-trash/<sync_id>/`。

### 3.2 自动同步

本机进入项目目录时，`.zshrc` 调用：

```bash
scripts/remote/start_auto_sync.sh --quiet
```

后台监控器每3秒生成一次可同步源码清单；同一内容指纹连续出现两次后才触发同步。最近成功指纹、PID、状态和日志保存在忽略的 `.remote/auto_sync/` 中。启动器使用 `nohup`，如果进程意外结束，下次进入项目目录时由 `.zshrc` 自动补启。

```bash
scripts/remote/start_auto_sync.sh
scripts/remote/status_auto_sync.sh
scripts/remote/stop_auto_sync.sh
```

自动同步不执行 Git commit 或 push。远端保护退出码含义：

| 退出码 | 含义 |
|---|---|
| 42 | 远端源码偏离上次同步清单 |
| 43 | 本地或远端已有同步任务 |
| 44 | 远端存在 `.sync-pause` 暂停标志 |
| 45 | 清单包含不安全路径，拒绝处理 |

### 3.3 冒烟测试快速同步

```bash
scripts/remote/sync_smoke.sh
```

该命令仅上传 PyTorch 冒烟测试所需文件，并运行哈希、Shell 语法和 Python 编译检查。日常研发默认使用整工作区同步。

## 4. 运行规范

### 4.1 run ID 与不可覆盖

- 每次运行使用唯一 `run_id`，建议格式为 `YYYYMMDD_任务_版本_seed`。
- 运行目录已存在时必须拒绝启动，不覆盖旧实验。
- `run_id` 只允许字母、数字、点、下划线和连字符。

### 4.2 长任务

长任务必须脱离 SSH 会话运行，优先级为：

1. 平台调度器/Slurm；
2. `tmux`；
3. 其他能明确保存日志和退出码的后台方式。

当前 PyTorch 冒烟任务已使用 `tmux`；SOFA 官方 demo 是最多 180 秒的同步验证。通用正式实验启动器尚未实现，不得将 SOFA demo 脚本当作长任务调度器。

### 4.3 正式实验元数据

每个正式实验目录至少包含：

```text
<run_id>/
├── config.yaml
├── metadata.json
├── stdout.log
├── exit_code
├── COMPLETE 或 FAILED
├── metrics.csv/json
└── 必需模型、图表或数据摘要
```

`metadata.json` 至少记录：

- Git commit 和工作区是否有未提交修改；
- 启动命令和配置快照；
- 随机种子；
- Python、依赖、SOFA 及插件版本；
- GPU、驱动、CUDA、主机和资源配额；
- 开始时间、结束时间和退出码。

## 5. 环境规范

### 5.1 PyTorch 冒烟环境

- Python：3.11；
- 当前环境：`/root/gpufree-data/continuum-runtime/envs/smoke-py311`；
- 创建/检查：`scripts/remote/setup_smoke_env.sh`。

非交互 SSH 不假设 Conda shell 初始化已加载；脚本显式使用 `/opt/conda/bin/conda`。创建环境时使用 `--override-channels`，避免受远程全局失效镜像影响。

### 5.2 SOFA 环境

- SOFA：v25.12.00，官方 Linux Python 3.10 预编译包；
- 安装入口：`/root/gpufree-data/continuum-runtime/sofa/v25.12.00-python3.10`；
- Python 环境：`/root/gpufree-data/continuum-runtime/envs/sofa-py310`；
- 已验证插件：SofaPython3、SoftRobots、STLIB；
- 官方包 SHA-256：`c88f6d23f8494b9ed100dffda1e73daadffc5428c395f9f64e36977fa3e6731a`。

SOFA 二进制和 Python 环境是可重建资源。实例释放或临时盘重置后，重新执行：

```bash
scripts/remote/install_sofa.sh /path/to/SOFA_v25.12.00_Linux-Python_3.10.zip
scripts/remote/check_sofa.sh
```

安装脚本会在本地和远程各执行一次官方包 SHA-256 校验。项目自建场景必须显式声明 `RequiredPlugin`，不依赖当前机器的偶然预加载状态。

## 6. 验收分层

### 6.1 源码与同步验收

- 本地语法检查和轻量测试通过；
- 远程 SHA-256 清单验证通过；
- 输出 `workspace_sync_verification=passed`。

### 6.2 运行完整性验收

- 存在 `COMPLETE`，不存在 `FAILED`；
- `exit_code` 为 0；
- 日志、配置、指标和任务必需产物存在且非空；
- 数值有限，并满足该任务预先定义的阈值/物理条件。

PyTorch 冒烟测试还会检查 CUDA/GPU 实际使用、损失下降、最终 MSE `< 1e-2`、指标一致性和预测行数，然后生成产物哈希清单。

### 6.3 回传验收

下载结束后，在本地重复运行语义检查并校验远程生成的产物哈希。哈希一致只证明传输完整，不证明物理模型或科研结论正确。

正式研究结论还需要单元测试、解析解/基准对比、数据泄漏检查、消融、多随机种子和实机验证。

## 7. 结果回传规范

默认拉回：

- 配置和 `metadata.json`；
- `stdout.log`、`exit_code` 和完成状态；
- 指标、图表、必要视频；
- 最优 checkpoint 或必要的小型模型产物。

默认不拉回：

- 全量原始轨迹；
- 每个 epoch 的 checkpoint；
- 镜像、环境、缓存和可重建中间文件。

需要分析大数据时，优先在远程生成统计摘要或抽样文件。

## 8. 安全与破坏性操作

- 密码、私钥、Token 不进入项目工作区，不上传远程，不写入日志。
- 不关闭 SSH 主机指纹检查。
- 不使用未经精确路径确认的递归删除或 `rsync --delete`。
- 删除大型数据前，核对目标路径、归档状态和是否可重建。
- 训练/仿真只能写入指定运行目录，遵守 GPU、CPU、内存和磁盘配额。
- 数据集按完整轨迹或 episode 切分，禁止随机打散相邻 transition 造成数据泄漏。
